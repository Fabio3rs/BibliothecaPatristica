OUTPUT CONTRACT CLARIFICATIONS — revision 1.1
Return the JSON object directly: the first non-whitespace character must be { and the last must be }. Do not wrap the response in Markdown fences.

IDs must be unique across ALL arrays. Use separate namespaces:
- concepts: c1, c2, ...
- entities: e1, e2, ...
- claims: p1, p2, ...
- events: v1, v2, ...
- relations: r1, r2, ...
- evidence: ev1, ev2, ... (never e1 or another entity ID).
Every evidence_ids entry points to an evidence ID such as ev1. Every relation endpoint points to a concept, entity, claim or event ID. Never use evidence IDs as endpoints.

Copy each evidence quote from exactly one supplied block or current summary segment. Preserve accents, ligatures, spelling, spaces, punctuation, line breaks (escaped as \n in JSON) and line-break hyphens. Do not join separated passages, silently repair OCR or change a word to its dictionary form. When a long quote is difficult to copy exactly, use a shorter contiguous supporting passage. If no reliable quote exists, omit the unsupported assertion or explain the limitation in warnings.

Use Portuguese for contextual meanings and proposition descriptions when the supplied summaries are Portuguese. Preserve original terminology in labels where useful and never translate source quotations.
