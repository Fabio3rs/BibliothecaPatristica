# Muse: literal Unicode navigation experiment

The experimental variant `navigation-v1.1-unicode-topics-arguments` adds
`tools/knowledge_graph/prompts/navigation_unicode_v1.rules.txt` to the existing
navigation v1 prompt. It keeps `kg-navigation-v1`, mode instructions, input
filtering and source preparation unchanged. Existing prompt variants are not edited.

The addition requests literal Unicode, including Portuguese accents, Latin ligatures
and Greek combining marks, without transliteration or spelling repairs in quotations.
Necessary JSON escaping remains allowed. This is a generation instruction, not a
validator rule: a correctly escaped `\u00e6` is still valid and equivalent to `æ`.
By contrast, `\u0000e6` decodes to NUL followed by `e6`; it is not repaired automatically.

The client already serialized JSON with `ensure_ascii=False` and used UTF-8.
The encoding calls now explicitly specify UTF-8 and strict errors. JSON requests
also advertise `Accept: application/json` and `Accept-Charset: utf-8` alongside
`Content-Type: application/json`. These headers cannot repair malformed escapes
generated by the service. JSON interoperability requires UTF-8, and no normative
`charset` parameter is defined for the media type ([RFC 8259, sections 8.1 and 11](https://www.rfc-editor.org/rfc/rfc8259.html)).

New received success-response bodies are captured before decoding in
`runs.result_json.http_response`, policy `kg-http-body-1`:

- `body_base64`: unchanged HTTP entity-body bytes, not HTTP headers or TCP framing;
- `sha256`, `byte_count`, `complete`, `status`, `encoding`;
- `utf8_valid`, and byte offsets if strict decoding fails.

The request Authorization header is never captured. Capture is omitted when a
known credential is reflected in the body. Oversized bodies are bounded at 32 MB;
the diagnostic records an incomplete prefix hash and does not archive it as a
complete response. Invalid UTF-8 or an invalid response envelope raises a stored
error without another model call. HTTP error handling retains its existing bounded,
redacted text diagnostic; full body capture applies to successfully received response
bodies. The decoded envelope (`provider_response`) and model content (`raw_response`)
remain available separately. Old responses cannot retroactively acquire byte captures.

For inspection, decode `http_response.body_base64`, verify its SHA-256, decode UTF-8,
then parse the envelope and inspect `choices[0].message.content`. Only then parse the
model's JSON. This separates transport encoding, envelope serialization and extraction
content. Located quotes and structurally valid JSON still do not establish semantic
correctness.

## Prepared real-page experiment

Prepared without inference:

- Experiment `EXP-ee6d17c4c705`, one planned run **1742**.
- Frozen case **1034**, **PG026:72**, reused from baseline run **1716**.
- Muse Spark 1.3 Contributor / Meta; reasoning `medium`; facsimile `on`;
  native JSON Schema output; 32,768 output tokens; cache bypass.
- Same source snapshot, user payload, image transport bytes, schema and provider
  configuration as 1716. The request body differs only in the system message.
- Current quote policy `local-quote-v6`; baseline 1716 used `local-quote-v5`.
  Thus compare Unicode corruption directly, not just the overall validation status.
- No editorial hints. One repetition is a smoke test, not a reliability estimate.

Machine-readable checks: `.work/kg_navigation_v1/muse_unicode_preflight.json`.

Preparation command used:

```bash
python scripts/playgrounds/kg_extractor_playground.py run \
  --case-ids 1034 --provider meta --model muse-spark-1.3-contributor \
  --prompts navigation-v1.1-unicode-topics-arguments \
  --mode concepts_relations --facsimile on --reasoning-effort medium \
  --repetitions 1 --bypass-cache --dry-run \
  --name 'Navigation Muse literal Unicode v1.1'
```

To initiate the prepared inference manually:

```bash
python scripts/playgrounds/kg_extractor_playground.py resume \
  --experiment EXP-ee6d17c4c705 --concurrency 1
```

Then inspect/report or compare:

```bash
python scripts/playgrounds/kg_extractor_playground.py report \
  --experiment EXP-ee6d17c4c705 --format markdown \
  --output .work/kg_navigation_v1/muse_unicode_report.md
python scripts/playgrounds/kg_extractor_playground.py compare --runs 1716 1742
```

Validation: 132 tests passed through Native Lab MCP, covering the new Unicode
regressions plus provider adapters, navigation, service tiers, playground execution
and statement review. All provider requests in tests were mocked. No inference
was performed during preparation. Schema/json-object/free-text comparisons remain
separate potential experiments; this preparation keeps schema enforcement fixed.
