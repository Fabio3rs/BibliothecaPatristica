# Semantic Unification for LLM Outputs: a second layer with embeddings and clustering

_Also available in Portuguese: [Versão em Português](LLM_unification_paper.md)

## Abstract
This document describes the motivation, architecture and recommended practices for adding a second semantic-similarity layer when working with large language models (LLMs). Due to the non-deterministic nature and textual variability of LLM outputs— even when semantically equivalent— it is necessary to apply embeddings, dimensionality reduction and clustering, followed by unification (canonicalization) strategies to achieve consistency, indexability and quality in pipelines that process keywords, citations and normalizations.

## Introduction
LLMs provide strong text understanding and generation capabilities. However, for tasks such as keyword normalization, citation extraction and canonical vocabulary construction, semantically equivalent outputs can appear in many textual surface forms. This variability hinders deduplication, similarity search and statistical analysis. A robust solution is to combine the LLM's power with an algorithmic layer using embeddings to group and unify results.

## Problem statement
- LLMs are non-deterministic: small prompt changes, temperature, or context can produce different text outputs.
- Same semantic unit => multiple textual forms (abbreviations, OCR errors, language variants, word order).
- We need a persistent canonical identifier for indexing, filters, cross-dataset linking and human evaluation.

## Proposal: second semantic layer
1. Generate embeddings for textual items (keywords, phrases, LLM outputs).
2. Reduce dimensionality (e.g., UMAP) to prepare for efficient large-scale clustering.
3. Apply a density/ hierarchical clustering method (e.g., HDBSCAN) to obtain semantic groups.
4. Select a canonical anchor per group (e.g., by membership_probability + length heuristics) and create a canonical names table.
5. For items processed by the LLM (e.g., normalization proposals), apply a "tournament" or reduction step where the LLM suggests merges and an aggregation algorithm (or another LLM) decides final canonicalization.
6. Persist mappings (original -> canonical) in a normalizations database and use those mappings throughout the pipeline.

- Normalizations via LLM

## Minimal contract (inputs/outputs)
- Inputs:
  - A set of strings (keywords, LLM outputs).
  - Embeddings (float32 numpy arrays) generated by a fixed model.
  - Metadata: item id, group_id (if applicable), model.
- Outputs:
  - Cluster table with membership probabilities and outlier scores.
  - Canonical names table: group_id -> canonical string (+ metadata: anchor_score).
  - Normalizations table: original -> canonical, persisted.
- Failure modes:
  - LLM call failures: implement retries, backoff, cache; log failures for human review.
  - Corrupt data or invalid embeddings: validate shapes and types before clustering.

## Implementation strategies & heuristics
- Embeddings: use a single consistent embedding model across the dataset. Store model version in metadata.
- UMAP: reduce to 10–50 dimensions depending on corpus size; keep a seed when reproducibility is required.
- HDBSCAN: use `membership_probability` and `outlier_score` to filter noise and identify anchors.
- Anchor selection: sort by membership_probability DESC, then by length heuristic (distance to mean), then alphabetically for deterministic tie-breaking; this heuristic is sketched in `fill_canon_keywords.py`.
- LLM `tournament_reduce`: send batches (e.g., 20–50 items) to the LLM, receive `change_to` proposals, apply transitive reduction and iterate until convergence. Use deterministic cache keys (sorted batch + system + model).
- Persistence: the `normalizations` table should be idempotent and unique on (original, group_id).

## Metrics and validation
- Purity / Cluster precision: fraction of items of the same concept placed in the same cluster.
- Anchor accuracy: how often the chosen anchor matches a human choice.
- Reduction stability: distance across tournament iterations (measure divergence or variance).
- Human-in-the-loop: stratified sampling of mappings for manual review; store decisions (reviewed_by, timestamp).

## Edge cases & limitations
- Large OCR noise can produce noisy embeddings; apply pre-embedding normalization (noise removal, strip control characters).
- Multilingual corpora: cross-lingual embeddings help, but policy decisions are needed (keep original vs translate).
- Citations without chapter/verse: requires a separate heuristic — `fill_canon_keywords.py` implements detection via `extract_citations_from_value_cached`.
- Very short tokens (1–2 chars) produce poor embeddings and should be treated specially.

## Suggested experiments
- A/B anchors: (a) probability only, (b) probability + length, (c) corpus frequency.
- Sensitivity analysis for UMAP/HDBSCAN parameters (n_neighbors, min_cluster_size).
- Measure impact of LLM batch size and temperature in `tournament_reduce` (stability vs quality).

## Security, ethics and governance
- Log prompts and LLM replies for audit. Avoid storing sensitive content without review.
- Provide a mechanism to programmatically revert normalizations if human review rejects changes.

## Practical implementation steps
1. Generate/confirm consistent embeddings for the full corpus (store model/version).
2. Run `hdbscan_embedding.py` to build initial clusters.
3. Create `cluster_canonical_names` using the SQL/heuristic in `fill_canon_keywords.py` (or a process considering membership_probability + average length).
4. For groups that require fine-grained normalization: run `ollama_keywords.py --group <id>` to collect LLM proposals and apply `tournament_reduce`.
5. Save mappings into the `normalizations` DB and ensure downstream consumers use these mappings for search/indexing.

## Conclusion
Combining LLMs with an algorithmic second layer based on embeddings, UMAP and HDBSCAN turns variable, non-deterministic outputs into stable canonical vocabularies. This approach balances LLM flexibility with the rigor needed for indexing, evaluation and interoperability across datasets.
